# ISDB-C 仕様ノート（ケーブルテレビの 64QAM トランスモジュレーション）

日本のケーブルテレビが BS/CS 放送を再送信する「トランスモジュレーション方式」の受信に必要な
仕様を、`ref/isdbc/` と `rt/isdbc/` の実装と対応づけてまとめる。

## 0. 情報源と照合状況（2026-10-13）

| 項目 | 一次情報 | 入手 | 備考 |
|---|---|---|---|
| 伝送路符号化・変調 | ITU-T J.83 (12/2007) Annex C「Digital multi-programme System C」 | 公開 PDF（itu.int）。本文テキストを抽出して照合 | JCTEA STD-002 の伝送方式は J.83 Annex C と同一。Annex C は「フレーム構成と誤り訂正は Annex A と同じ、ロールオフとシンボルレートが 6 MHz 向け」 |
| Annex A の詳細（式・図） | ETSI EN 300 429 V1.2.1（DVB-C） | 公開 PDF（etsi.org）。本文・図のラベル文字列を抽出 | 64QAM 配置の図 7、表 1（象限変換）、差動符号化の式 |
| 複数 TS 多重（TSMF） | ITU-T J.183 (03/2001) + Appendix I（J.83 Annex C 向け運用値） | 公開 PDF | ヘッダの固定値（PID、同期語、frame_type）は J.183 本文では「システムが定める」。運用値は JCTEA STD-002 側で、ここでは受信機実装（BonDriver_BDA の TSMF.cpp）と実放送で確認 |
| 差動符号化の否定の位置 | 上記 PDF の数式はテキスト抽出で判別不能 | US6226333（Google Patents のテキスト）で確認、さらに回転不変性の自己検査（`mapping._build_phase_tables`）で確定 | 2026-10-13 |
| **実放送照合** | ケーブル TV 宅内端子、UHF 56ch（731 MHz、NHK BS、TS_id 16625）、54ch（BS 日テレ 16592）、49ch（BS 朝日 16400） | Pluto SDR 7.111 MSPS 録音 → `ref/isdbc` で RS 訂正不能 0、PAT の TSID 一致 | 2026-10-13。49ch は TSMF 無しの単一 TS だった |

J.83 Annex C 本文はシンボルレートの数値を書いていない（「6 MHz チャンネルに最適化」とだけ）。
5.274 Mbaud は JCTEA STD-002 の値で、ここでは BonDriver_BDA の設定（5274 ksym/s）と実放送のスペクトル
（−3 dB 幅 5.17 MHz ≈ Rs(1+α)/… の整合、タイミング推定の偏差 +15 ppm = Pluto の XO 誤差と同程度）で裏付けた。
`# VERIFY` を付けた項目は JCTEA STD-002 原本での照合が未了。

## 1. 伝送路の基本（J.83 C.6）

| 項目 | 値 | 根拠 |
|---|---|---|
| 変調 | 64QAM（256QAM も規定、未実装） | C.6.3 |
| シンボルレート | 5.274 Mbaud（# VERIFY: JCTEA STD-002） | 6 MHz チャンネル |
| ロールオフ | α = 0.13（ルートレイズドコサイン、送受で分担） | C.6.4 |
| 占有帯域 | Rs(1+α) = 5.96 MHz、−3 dB 幅 = Rs = 5.274 MHz | C.6.5 |
| 有効 TS レート | 5.274 M × 6 × 188/204 = 29.16 Mbps | 計算 |
| チャンネル周波数 | 中心 = 6 MHz 格子。UHF 13ch = 473 MHz、VHF 1ch = 93 / 4ch = 171 MHz、C13 = 111 / C23 = 225 MHz（+1/7 MHz オフセットは無い） | BonDriver_BDA の TransModulation 表と実放送（731.000 MHz で CFO +11 kHz = Pluto XO 分） |

## 2. フレーム構成と誤り訂正（J.83 C.4 / C.5 = Annex A）

ISDB-T（STD-B31 3.5〜3.7）と同じ部品なので `isdbt.fec` を共用する。

| 段 | 内容 | 実装 |
|---|---|---|
| 同期バイト反転 | 8 パケットごとに先頭パケットの 0x47 を 0xB8 にする | `framing.scramble` |
| ランダマイズ | PRBS 1 + x^14 + x^15、初期値 100101010000000、8 パケットごとに初期化。最初の出力ビットは 0xB8 直後のバイトの MSB。他 7 パケットの同期バイトの間は PRBS が進むが出力しない → 周期 1503 バイト | `framing._PRBS_PAYLOAD`（パケット i のペイロードは PRBS[188 i : 188 i + 187]） |
| RS | (204,188) t=8、生成多項式 (x+λ^0)…(x+λ^15)、λ=02h、体 x^8+x^4+x^3+x^2+1。同期バイトも符号化対象 | `isdbt.fec.rs_encode / rs_decode` |
| 畳み込みインターリーブ | Forney 型 I=12、M=17。同期バイトは必ずブランチ 0（遅延なし）→ 204 バイト周期が保たれる | `isdbt.fec.byte_interleave / byte_deinterleave`（整数パケット分の一定遅延を除いて同一。受信側はブランチ b を 11−b パケット遅延、先頭 11 TSP は不定） |

受信側の同期: インターリーブ後も同期バイトは 204 バイト周期の同じ位置に残るので、デインターリーブ前に
0x47/0xB8 の 204 周期一致率でバイト境界を決める（`framing.sync_score`）。8 パケットグループの位相は
RS 訂正後の 0xB8 の行番号で決める（`decode_stream`）。

## 3. バイト → シンボル、差動符号化、コンスタレーション（J.83 C.6.1〜C.6.3）

- **バイト → m タプル**（C.6.1、EN 300 429 図 5）: シンボル Z の MSB = バイト V の MSB、以下順に。
  64QAM は 3 バイト → 4 シンボル（MSB ファースト詰め）。Z が Z+1 より先に送られる。
- **2 MSB の差動符号化**（C.6.2、EN 300 429 第 8 節）:
  ```
  I_k = ¬(A_k ⊕ B_k)·(A_k ⊕ I_{k−1}) + (A_k ⊕ B_k)·(A_k ⊕ Q_{k−1})
  Q_k = ¬(A_k ⊕ B_k)·(B_k ⊕ Q_{k−1}) + (A_k ⊕ B_k)·(B_k ⊕ I_{k−1})
  ```
  否定（オーバーバー）が第 1 項の (A⊕B) に掛かる（US6226333 の引用と一致）。第 2 項に掛ける読みだと
  π/2 回転に対して不変にならない（`mapping._build_phase_tables` が総当たりで検査し、不変な巡回順
  00 → 10 → 11 → 01 を見つける。見つからなければ import 時に assert で止まる）。
  この式は「象限位相 p_k = p_{k−1} + d(A,B) mod 4」と等価で、d(00)=0, d(10)=1, d(11)=2, d(01)=3
  （反時計回り）。`diff_encode` は累積和で、`diff_decode` は位相差で実装。
- **象限の変換**（EN 300 429 表 1）: 第 1 象限 I_k Q_k = 00（右上）、第 2 象限 10 = +π/2（左上）、
  第 3 象限 11 = +π（左下）、第 4 象限 01 = +3π/2（右下）。LSB の配置は第 1 象限を回転したもの。
- **第 1 象限の 4 LSB (b3 b2 b1 b0)**（J.83 図 C.7 / EN 300 429 図 7 から転記。行 = Q、列 = I）:

  | Q \ I | 1 | 3 | 5 | 7 |
  |---|---|---|---|---|
  | 7 | 1000 | 1001 | 1101 | 1100 |
  | 5 | 1010 | 1011 | 1111 | 1110 |
  | 3 | 0010 | 0011 | 0111 | 0110 |
  | 1 | 0000 | 0001 | 0101 | 0100 |

  つまり I のレベル 1,3,5,7 ↔ (b2 b0) の Gray 符号 00,01,11,10、Q のレベル ↔ (b3 b1) の Gray 符号。
  図の向き（どの行が Q=7 か）は、第 2 象限の行「101000 101010 100010 100000」（左から I = −7..−1、Q = +1）が
  第 1 象限の左列を +90° 回転したものと一致することで確定した。
- 256QAM（図 C.7 Part 2）は図が画像でラベルを抽出できておらず未実装（TODO）。

## 4. 受信機（ref/isdbc/demod.py）

| 段 | 方法 | 備考 |
|---|---|---|
| リサンプル | 任意 fs → 2 sps（有理数比） | 実際の 2 sps レートは 2Rs と ppm 級でずれるがタイミング推定が吸収 |
| 粗 CFO | スペクトルの平坦部から外へ向かって最初に −3 dB を切る点（RRC では ±Rs/2）の中点 | 隣接チャンネルは自チャンネルの端より外なので影響しない |
| 整合フィルタ | RRC α=0.13、±16 シンボル | |
| タイミング | Oerder–Meyr（ブロックを 4 sps に補間して Σ|y|² e^{−j2πn/4}）→ 1 シンボル周期で unwrap → 直線フィット → 多相 sinc 補間 | 2 sps ではシンボルレート線がナイキストに重なり位相が取れない |
| 微 CFO | z^4 の FFT ピーク / 4 | 64QAM は E[z^4] < 0（= −1092 at レベル ±1..±7）なので位相は arg(−Σz^4)/4 |
| 位相・等化 | ブロック 4 乗法位相 → 判定指向 LS の T 間隔 FFE（25 タップ）→ 判定指向ブロック位相（256 シンボル） | ケーブルの短い反射向け |
| ビット境界 | 差動復号後の 6 ビット語列に対し 24 通りのビット境界で 204 周期同期一致率を比較 | |
| スペクトル反転 | 同期一致率 < 0.5 なら共役で再試行 | |

rt/isdbc（逐次版）の相違点: 入力レートの多相 RRC 補間で 2 sps を作らずシンボルを直接抽出、O&M はブロックごと、
LS 等化は 32 シンボルおきに保存したベクトルから位相ブロック末尾で R を積算し 2048 本ごとに解く、RS は 32 TSP ずつ
`isdbt::RsDecode`（AVX2）へ。

必要 C/N: 内符号が無いので 64QAM は RS 限界が MER ≈ 22 dB 付近（ループバック: 標本化帯域基準 C/N 18 dB で
RS ほぼ全滅、24 dB で誤りなし）。

## 5. TSMF（ITU-T J.183、Appendix I の運用値）

- フレーム = 53 スロット × 188 バイト（ヘッダ 1 + TS パケット 52）。最大 15 TS、相対 TS 番号 1..15（4 ビット）。
- ヘッダパケット: PID 0x002F（# VERIFY: J.183 は「他と重ならない値」とだけ規定。BonDriver_BDA と実放送で確認）、
  バイト 3 の上位ニブル 0001、TSMF_sync = 上位 3 ビット reserved + 13 ビット 0x1A86（反転 0x0579 も受理。
  # VERIFY: 交互反転の運用）、version(3) + slot_allocation_type(1) + frame_type(4)、availability 15 ビット、
  (TS_id, original_network_id) × 15、receive_status 2 ビット × 15、emergency_indicator、
  relative_TS_number 4 ビット × 52、private_data 85 バイト、CRC_32（MPEG-2 と同じ、バイト 4..187 で余り 0）。
  配置の詳細は `ref/isdbc/tsmf.py` 冒頭。
- 受信: ヘッダを見つけたら以降 52 スロットをヘッダの relative_TS_number 表で選別する。
  TS を 1 本だけ載せる局でも TSMF が付くことがある（56ch/54ch）し、付かないこともある（49ch）。
  `tsmf.demultiplex` は TSMF が無ければ入力をそのまま返す。
- 選択: 既定は有効 TS のうち最小の相対 TS 番号。相対 TS 番号または (ONID, TS_id) でも選べる。
  BonDriver_BDA の「相対 TS 未指定」はヘッダ含め全スロット通過（`select="all"`）に相当。

## 6. 受信レベル（AD9363 の過大入力）— 2026-10-13 実測

ケーブル端子は全チャンネルが強く、ハードウェア AGC（slow_attack、約 −11 dBFS）ではフロントエンドが
歪んで MER が 20 dB（64QAM の RS 限界以下）に張り付いた。手動ゲインで掃引すると:

| ゲイン | 帯域内レベル | MER（56ch） |
|---|---|---|
| AGC（42 dB） | −11 dBFS | 20.0 dB |
| 38 / 36 / 33 dB | −16 / −18 / −21 dBFS | 20.1 dB |
| 30 dB | −22 dBFS | 33.1 dB |
| 27 dB | −25 dBFS | 33.0 dB |
| 24 dB | −28 dBFS | 31.2 dB |
| 20 / 10 dB | −32 / −42 dBFS | 29.9 / 24.8 dB |

ゲイン 30 → 33 dB の間に急な崖がある（全帯域の合計入力電力による圧縮）。地デジ（ISDB-T）も同じ端子で
AGC だと A 17.9 / B 19.8 dB だったものがゲイン 30 dB で A 23.6 / B 27.0 dB（24ch）、A 24.5 / B 30.1 dB（27ch）
になった。受信機は帯域内レベルを約 −24 dBFS に保つソフトウェア AGC を既定にする（`SdrConfig`）。
