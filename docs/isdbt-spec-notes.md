# ISDB-T 仕様ノート（ARIB STD-B31 要約）

このファイルは `ref/isdbt/params.py` の根拠を書く場所。値を追加・変更するときは
STD-B31 の章・表番号を必ず併記する。「VERIFY」と書かれた項目は仕様書原本と未照合。

## 3. 誤り訂正（3.3〜3.8）
- 処理順（送信側、図 3-2）: TS 再多重 → RS(204,188) → 階層分割 → エネルギー拡散 → 遅延調整 → バイトインターリーブ → 畳み込み符号（バイト→ビットは MSB first）
- 外符号 RS(204,188)（3.3）: GF(2^8)、原始多項式 x^8+x^4+x^3+x^2+1、g(x) = Π(x − α^i), i=0..15、α=02h。
  先頭 51 バイトの 00h を付けた RS(255,239) の短縮。同期バイトも符号化対象（図 3-6）
- 階層分割（3.4）: 伝送 TSP は「同期バイトの次のバイトから次の同期バイトまで」の 204 バイト。
  **OFDM フレーム同期は 1 バイトずれて情報バイトの先頭になる**（図 3-7）。
  → 伝送路上の 204 バイトの並びは [情報 187, パリティ 16, 同期バイト]
- エネルギー拡散（3.5、図 3-8）: PRBS x^15+x^14+1、初期値 100101010000000（左が段 1）。
  **各 OFDM フレームで初期化**。フレーム先頭は「同期バイトの次のバイトの MSB」。同期バイトは XOR しないが
  レジスタは同期バイト中もシフトする。出力系列の先頭は 03 F6 08 34 …（DVB と同一）
  - 1 フレームの TSP 数 = nseg·dc·bits·rate/8（Mode 3 QPSK 2/3 1seg: 64、64QAM 3/4 12seg: 2592）
- バイトインターリーブ遅延調整（3.6、表 3-7）: (TSP/フレーム/セグメント)·N − 11 TSP。合計遅延 1 フレーム
- バイトインターリーブ（3.7、図 3-9）: 畳み込み型、12 パス × 17 バイト。**同期バイトの次のバイトがパス 0（遅延なし）**
- 内符号（3.8、図 3-10、表 3-8）: 拘束長 7、G1=171（X）、G2=133（Y）（8 進）。
  パンクチャは **フレーム同期で位相をリセット**。送出順: 1/2 X1 Y1 / 2/3 X1 Y1 Y2 / 3/4 X1 Y1 Y2 X3 /
  5/6 X1 Y1 Y2 X3 Y4 X5 / 7/8 X1 Y1 Y2 Y3 Y4 X5 Y6 X7（DVB-T と同一）

## 4. キャリア変調・インターリーブ（3.9〜3.11）
- ビットインターリーブ遅延調整（3.9.2、表 3-9）: Mode 3 で QPSK 1536N−240、16QAM 3072N−480、
  64QAM 4608N−720 ビット（N = 階層のセグメント数）。インターリーブ遅延 120 キャリアシンボルと
  合わせて **送受合計 2 OFDM シンボル**
- ビットインターリーブ（図 3-14/16/18）: QPSK b1 に 120、16QAM b1..b3 に 40/80/120、
  64QAM b1..b5 に 24/48/72/96/120 の遅延。b0 は遅延 0
- マッピング（図 3-15/17/19）: b0 が I の符号、b1 が Q の符号（0 → 正）。
  16QAM は (b0,b2) が I、(b1,b3) が Q。64QAM は (b0,b2,b4) が I、(b1,b3,b5) が Q。
  振幅はグレイ符号: 16QAM b2=0→3、1→1。64QAM (b2,b4)=00→7, 01→5, 11→3, 10→1
- 正規化（表 3-11）: QPSK Z/√2、16QAM Z/√10、64QAM Z/√42（平均電力 1）
- 階層合成（3.10、図 3-21）: 各階層の直列シンボルをその階層のデータセグメント（番号順）に詰める。
  セグメント番号は階層 A から順に 0,1,2,…（3.11.2）
- 時間インターリーブ（3.11.1、図 3-23、表 3-12）: キャリア i の遅延 = I × m_i、m_i = (i × 5) mod 96。
  遅延調整（インターリーブ前）: Mode 3 I=1: 109、I=2: 14、I=4: 28 / Mode 2 I=2: 14、4: 28、8: 56 /
  Mode 1 I=4: 28、8: 56、16: 112 シンボル。I=0 は 0。送受合計は整数フレーム
- 周波数インターリーブ（3.11.2、図 3-25）:
  1. セグメント間（図 3-26）: **部分受信部・差動変調部・同期変調部のグループごと**に、階層をまたいで実施。
     グループ内の直列 S_q（セグメント順に連結）→ セグメント q mod n、キャリア q div n。
     部分受信セグメントは対象外
  2. セグメント内キャリアローテーション（図 3-27）: セグメント番号 k で、出力位置 j = 入力 (j + k) mod N
     （入力 c → 出力 (c − k) mod N）
  3. セグメント内ランダマイズ（表 3-13 (a)(b)(c)）: 位置 r → perm[r]（`ref/isdbt/tables/carrier_randomize.py`）
- **処理順の注意（実放送で検証済み・2026-10-10）**: セグメント間インターリーブは
  周波数インターリーブの一部であり、**時間インターリーブ（3.11.1）の後**に行う。
  当初は変調器・復調器の双方が「階層合成直後（時間の前）」に置く同一の誤りを持っており、
  ループバックでは検出できなかった（鏡像実装のため）。実放送（物理24ch、部分受信構成）では
  セグメント 0 がグループ外のため A 階層のみ復号でき、B 階層が全滅する症状で発覚。
  順序修正後に B 階層の RS 訂正が通ることを実波で確認した。

## 5. フレーム構成・パイロット（3.12〜3.14）
- 同期変調部（図 3-30）: SP は k mod 12 = 3·(n mod 4)（キャリア方向 12 本おき、シンボル方向 4 周期）
- TMCC / AC1 位置（表 3-15 (a)(b)(c)、セグメント相対、列は周波数順）: `ref/isdbt/tables/pilot_positions.py`
- 差動変調部（表 3-14 (a)(b)(c)）: CP = キャリア 0、AC1 は同期変調部と同じ、AC2 と TMCC は別表（転記済み）
- パイロット PRBS（3.13.1、図 3-31）: **g(x) = x^11 + x^9 + 1**、全 1 で初期化し帯域左端から全キャリア分を
  連続生成（表 3-16 の各セグメント初期値はその途中状態。テストで一致確認済み）
- W_i と振幅（表 3-17）: W=0 → (+4/3, 0)、W=1 → (−4/3, 0)。SP/CP/TMCC/AC すべて同じ
- CP（3.13.2）: 位相はシンボルによらず一定。右端 CP（表 3-19）: Mode 1 −4/3、Mode 2/3 +4/3
- TMCC（3.13.3）: DBPSK。B'_0 = W_i、B'_k = B'_{k−1} ⊕ B_k、差動符号化後 0 → +4/3、1 → −4/3
- AC（3.13.4、3.16）: DBPSK、基準はフレーム先頭シンボルで W_i。付加情報が無ければスタッフィング 1。
  AC1 は全セグメント同一位置、AC2 は差動変調部のみ。緊急地震速報はセグメント 0 の AC（表 3-32〜）
- RF 信号（3.14.1）、GI（3.14.2、図 3-33）: IFFT 出力の末尾を先頭に付加

## 6. TMCC（3.15）
- ビット割当（表 3-20）: B0 基準、B1〜B16 同期語（w0 = 0011010111101110、w1 = 反転、フレームごとに交互、表 3-21）、
  **B17〜B19 セグメント形式識別: 差動 111、同期 000**（3.15.5）、B20〜B121 情報、B122〜B203 パリティ
- 情報部（表 3-22）: B20-21 システム識別（00 = 地上テレビ、表 3-24）、B22-25 切替指標（通常 1111、表 3-25）、
  B26 緊急警報起動フラグ（表 3-26）、B27 部分受信フラグ（表 3-27）、B28-40/41-53/54-66 階層 A/B/C（現在）、
  B67 次の部分受信フラグ、B68-106 階層 A/B/C（次）、B107-109 位相補正（全 1）、B110-121 予備（全 1）
- 階層情報 13 ビット（表 3-23）: 変調 3（表 3-28）、符号化率 3（表 3-29）、I 3（表 3-30）、セグメント数 4（表 3-31、2 進）
- パリティ（3.15.6.9）: (184,102) 短縮差集合巡回符号、(273,191) の生成多項式
  x^82+x^77+x^76+x^71+x^67+x^66+x^56+x^52+x^48+x^40+x^36+x^34+x^24+x^22+x^18+x^10+x^4+1

## 8. 受信機側で押さえる数値
- フルセグ所要 C/N: 64QAM 3/4 でおよそ 20〜22 dB（AWGN）
- ワンセグ所要 C/N: QPSK 2/3 でおよそ 6〜7 dB
- 周波数オフセット想定: ±25 ppm @ 470〜710 MHz → 最大 ±18 kHz（互換機はより大きい可能性）
- 隣接チャンネル: 6 MHz 間隔で連続割当。中心 ±3.21 MHz から隣接が始まる

## 10. フレーム整合の規約（変調器・復調器で共有）
送信側の各遅延調整は「合計遅延 = 整数フレーム（バイト: 3.6、時間: 表 3-12）／2 シンボル（ビット: 3.9.2）」に
なるよう定められている。整数フレームのずれは電波上で区別できないため、`modulator.py` は遅延を「先読み」に
置き換え、**OFDM フレームの先頭シンボルに各階層の TSP 境界が来る**ように生成する。
3.8 の「パンクチャパターンはフレーム同期で初期化」、3.5 の「PRBS はフレーム先頭で初期化」、
3.7 の「同期バイトの次のバイトがパス 0」もこの規約と整合する。
gr-isdbt の送信例もフレーム構成の直前で 2 シンボル捨てて同じ整合にしている。

受信側の補遅延（仕様どおり）:
| 段 | 送信側 | 受信側 | 合計 |
|---|---|---|---|
| バイト | パス b を b TSP | 11 − b TSP | 11 TSP（+ 調整で 1 フレーム）|
| ビット | b_i を d_i（+ 調整）| 120 − d_i | 2 シンボル |
| 時間 | I·m_i（+ 調整）| I·(95 − m_i) | 整数フレーム |

したがって復調器は、TMCC で確定したフレーム先頭から数えて、上記補遅延を入れた後の
ビット列の先頭が TSP 境界（PRBS 初期化点、パンクチャ位相 0、パス 0）と見なしてよい。

## 11. BTS（放送 TS、204 バイト多重フレーム）— 2026-10-10 原本照合
`ref/isdbt/bts.py` の根拠。すべて STD-B31 v2.2-E1 の該当箇所と突き合わせた。

- 多重フレーム長（表 3-5）: 1 多重フレームの伝送 TSP 数。
  Mode 1: 1280/1152/1088/1056、Mode 2: 2560/2304/2176/2112、Mode 3: 5120/4608/4352/4224
  （GI 1/4, 1/8, 1/16, 1/32 の順）。= symbol_samples × 204 / 408（伝送 TSP クロックは
  FFT サンプルクロックの 4 倍、3.2.1）。テストで全 12 値を照合済み。
- スロット配置: モデル受信機（3.2.2、図 3-4）の動作で間接的に規定される。
  - 階層分割入力はセグメント番号順・キャリア番号順、1 キャリアシンボル = 1 クロック（3.2.2.1、図 3-5）
  - 階層バッファへの蓄積 B_X,k = 2(⌊k·Sx·Rx⌋ − ⌊(k−1)·Sx·Rx⌋)、Sx は表 3-6
    （DQPSK/QPSK: 2、16QAM: 4、64QAM: 6）。408 バイトで 1 TSP 完成（3.2.2.2）
  - TS 再生部は 2 系統。S3（入力）は Mode 1: フレームごと、Mode 2: 102 シンボル、
    Mode 3: 51 シンボルで交互切替。S4（出力）は S3 の 3 TSP 周期後に追従（3.2.2.2）
  - TS 再生部は TSP 周期（408 クロック）ごとにバッファを確認し、無ければヌル TSP
- ISDB-T 情報（添付 5.5.2、表 5-6 / 5-7）: 188 バイトの直後 8 バイト。
  byte0 = TMCC 識別 '10' + reserved '1' + 各フラグ + フレーム頭 + 偶奇、
  byte1 = 階層表示（0000 ヌル / 0001 A / 0010 B / 0011 C / 0100 AC / 1000 IIP）+ 切替指標、
  byte2-3 = AC 無効 '1' + AC 有効バイト '11' + TSP カウンタ 13 ビット、byte4-7 = AC またはスタッフィング
- パリティ（添付 5.5.2 (1)、オプション）: 短縮 RS(204,196)。原始多項式は本編 3.3 と同じ
  x^8+x^4+x^3+x^2+1、生成多項式の根は λ^0..λ^7（λ = 02hex）
- 未対応: Mode 1 の 2 フレーム周期パターン（S3 がフレーム単位のため。日本の実運用は Mode 3）、
  IIP（ISDB-T Information Packet、添付 5.5.3）、AC データの多重
